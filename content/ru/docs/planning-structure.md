## Цель { #planning-structure }

Составить план структуры контента сайта (какие типы и подтипы сущностей использовать для разных видов контента), а также определить, на каких страницах будут выводиться списки материалов.
## Необходимые знания

* [planning-data-types](./planning-data-types.md)
* [planning-modular](./planning-modular.md)
* [preface-scenario](./preface-scenario.md)
## Шаги

1. Определите, какой контент должен быть на сайте. Подумайте, какую информацию будут искать посетители, а также что вы сами хотите им показать. Получившийся список может выглядеть так, как в разделе [preface-scenario](./preface-scenario.md).
1. Для каждого типа информации решите, какой тип сущности Drupal подходит лучше всего. Важно учитывать, где и как контент будет использоваться и кем редактироваться. Например, на сайте городского рынка часы работы и адрес лучше всего оформить как отдельный пользовательский блок, чтобы разместить его в боковой колонке на всех страницах. А страницы производителей удобнее сделать как материалы (node), чтобы каждый производитель мог редактировать свои данные — права доступа ядра Drupal это позволяют.
    Обратите внимание, что иногда нет единственно правильного варианта: например, производителей можно реализовать как отдельные пользовательские профили, но тогда страница производителя будет жестко связана с определенной учетной записью, и поменять владельца такой страницы будет сложнее.
1. Для каждого выбранного типа сущности определите, какие подтипы нужны. В нашем примере с рынком для сущности “Материал” (Content item) могут быть подтипы “Обычная страница” (например, Главная и О сайте), “Производитель” и “Рецепт”.
1. Для каждого подтипа продумайте необходимые поля. Например, для “Производителя” понадобятся поля: имя, URL сайта, изображение и описание.
1. Определите, какие списки материалов нужны на сайте: это могут быть отдельные страницы или блоки в определенных областях. Для каждого списка решите, какие материалы туда будут попадать, в каком порядке и с какими фильтрами. Например, для страницы рецептов удобно сделать фильтрацию по ингредиентам, а значит, у типа материала “Рецепт” должно быть поле “Ингредиенты”.
1. Для каждого поля определите его тип (текст, форматированный текст, дата, изображение и т. д.) и количество значений. Большинство полей бывают однозначными, но, например, для ингредиентов в рецепте понадобится множественное поле.
1. Подумайте, какие поля стоит сделать ссылками на термины таксономии (то есть выбирать значения из заранее определенного списка). Это удобно для значений, которые могут регулярно пополняться. Например, ингредиенты для рецепта — отличный кандидат для таксономии.
1. Если необходимо, определите поля-ссылки на другие сущности контента. Например, если производители будут отправлять рецепты, добавьте в “Рецепт” поле-ссылку на материал “Производитель”, чтобы связать рецепт и его автора.
