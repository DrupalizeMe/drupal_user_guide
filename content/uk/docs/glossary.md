## Ajax { #glossary-ajax }

Веб-технологія, яка використовується для обміну даними з сервером для динамічного оновлення частин сторінки (наприклад, форм) без необхідності перевантаження сторінки повністю.

## GPL { #glossary-gpl }

Акронім для _GNU General Public License_ (Загальна публічна ліцензія), не комерційна ліцензія програмного забезпечення. На все програмне забезпечення звантажене з веб-сайту [_Drupal.org_](https://www.drupal.org) розповсюджується ліцензія ["GNU General Public License, version 2"](http://www.gnu.org/licenses/old-licenses/gpl-2.0.html). Дивіться також [ВВПЗ](./glossary.md#glossary-foss). Дивіться [understanding-gpl](./understanding-gpl.md) для додаткової інформації.

## LAMP { #glossary-lamp }

Акронім для _Linux, Apache, MySQL, and PHP_: програмне забезпечення для веб-серверу, який, зазвичай, опрацьовує сценарії (хоча для цього можуть бути використані і інші операційні системи, веб-сервери, та бази даних). Дивіться [install-requirements](./install-requirements.md) для додаткової інформації.

## WYSIWYG { #glossary-wysiwyg }

Акронім для _What You See is What You Get_ (Що бачиш, те й отримуєш), означає метод для редагування [вмісту](./glossary.md#glossary-content), що ви бачите під час редагування на екрані близько нагадує кінцевий продукт. Дивіться [structure-text-format-config](./structure-text-format-config.md) для додаткової інформації.

## Адаптивний { #glossary-responsive }

Сайт або [тема](./glossary.md#glossary-theme) вважаються адаптивними якщо вони коректують своє відображення відповідно до розміру екрану браузера, принтера або іншого пристрою для відображення медіа. Дивіться також [точка переходу](./glossary.md#glossary-breakpoint). Дивіться [structure-image-responsive](./structure-image-responsive.md) для додаткової інформації.

## Анонім { #glossary-anonymous }

Особа ([користувач](./glossary.md#glossary-user)) що користується сторінкою без авторизації. Дивіться [user-concept](./user-concept.md) для додаткової інформації.

## Блок { #glossary-block }

Частина [матеріалу](./glossary.md#glossary-content) (текст, зображення, посилання, і т.д.) що може бути відображення на сторінці сайту. Блок відображається у [регіоні](./glossary.md#glossary-region). Дивіться [block-concept](./block-concept.md) для додаткової інформації.

## ВВПЗ { #glossary-foss }

Акронім для _вільного та відкритого програмного забезпечення_, мається на увазі програмне забезпечення, що розроблене спільнотою і опубліковане під не комерційною ліцензію. Дивіться також [GPL](./glossary.md#glossary-gpl). Дивіться [understanding-project](./understanding-project.md) для додаткової інформації.

## Віджет { #glossary-widget }

Дивіться [Віджет поля](./glossary.md#glossary-field-widget).

## Віджет поля { #glossary-field-widget }

[Конфігурація](./glossary.md#glossary-configuration) що визначає як хто-небудь вводить або редагує дані для [поля](./glossary.md#glossary-field) у формі введення даних. Наприклад, текстове поле може використовувати одно або багато рядковий елемент форми. Дивіться також [Форматер поля](./glossary.md#glossary-field-formatter). Дивіться [structure-widgets](./structure-widgets.md) для додаткової інформації.

## Вид { #glossary-view }

Відформатований список даних; зазвичай, дані надходять з [сутностей](./glossary.md#glossary-entity) [матеріалу](./glossary.md#glossary-content). Наприклад, на сайті фермерського ярмарку, ви можете створити [матеріал](./glossary.md#glossary-content-item) для кожного продавця. Далі ви можете створити вид що генерує список сторінок, який показує мініатюрні зображення та короткий опис кожного продавця, посилаючись на сторінку повного матеріалу. Використовуючи ті самі дані ви також можете створити новий блок, який відображатиме інформацію про останніх доданих продавців. Дивіться [planning-modular](./planning-modular.md) для додаткової інформації.

## Вміст { #glossary-content }

Інформація призначена для відображення на вашому сайті, наприклад текст, зображення, звантаження і т.і. Дивіться також [Конфігурація](./glossary.md#glossary-configuration) і [Стан](./glossary.md#glossary-state). Дивіться [understanding-data](./understanding-data.md) для додаткової інформації.

## Внесені { #glossary-contributed }

[Модулі](./glossary.md#glossary-module), [теми](./glossary.md#glossary-theme), та [дистрибутиви](./glossary.md#glossary-distribution), що не являються частиною [ядра Drupal](./glossary.md#glossary-drupal-core), які ви можете звантажити окремо з веб-сайту [_Drupal.org_](https://www.drupal.org)

## Дистрибутив { #glossary-distribution }

Одиноразове звантаження, що дає можливість встановити певний тип сайту, наприклад сайт для клубу або інтернет-магазину. Дистрибутив містить в собі [ядро Drupal](./glossary.md#glossary-drupal-core), разом з [внесеними](./glossary.md#glossary-contributed) [модулями](./glossary.md#glossary-module) та/або [темами](./glossary.md#glossary-theme); більшість дистрибутивів, також, виконують попередню конфігурацію сайту або створюють приклади вмісту під час інсталяції. Дивіться [understanding-distributions](./understanding-distributions.md) для додаткової інформації.

## Дозвіл { #glossary-permission }

Можливість виконувати деяку дії на сайті, такі як редагування конкретного типу [матеріалу](./glossary.md#glossary-content), або переглядання користувацьких профілів. Дивіться також [Роль](./glossary.md#glossary-role). Дивіться [user-concept](./user-concept.md) для додаткової інформації.

## Журнал { #glossary-log }

Перелік записаних подій на сайті, таких як використання даних, дані про продуктивність, помилки, застереження та оперативна інформація. Дивіться [prevent-log](./prevent-log.md) для додаткової інформації.

## ІК { #glossary-ui }

Акронім для [_Інтерфейс користувача_](./glossary.md#glossary-user-interface).

## Інтерфейс користувача { #glossary-user-interface }

Текст, стилі, зображення, які видно на сайті, що розділені логічно на інтерфейс користувачів для відвідувачів сайту та адміністративний інтерфейс.

## Кеш { #glossary-cache }

Внутрішнє кешування сайту зберігає виведення, яке потребує значних витрат часу, наприклад для обчислення виведення запиту HTML-сторінки, і потім використовує збережені дані, замість повторного обчислення, коли вони потрібні наступного разу. На веб-сервері також може бути використане зовнішнє кешування для пришвидшення відповіді сайту. Дивіться [prevent-cache](./prevent-cache.md) для додаткової інформації по внутрішньому кешуванню.

## Контекстне посилання { #glossary-contextual-link }

Посилання на адміністративну сторінку для редагування або конфігурації функціональних можливостей сайту, показується відповідно до відображених функцій. Наприклад: посилання для конфігурації [меню](./glossary.md#glossary-menu) показане коли ви наводите мишкою на меню. Дивіться [config-overview](./config-overview.md) для додаткової інформації.

## Конфігурація { #glossary-configuration }

Інформація про ваш сайт, яка не є [матеріалом](./glossary.md#glossary-content), і яка призначена бути більш сталою та постійною, ніж інформація про [стан](./glossary.md#glossary-state). Наприклад назва вашого сайту, [типи матеріалу](./glossary.md#glossary-content-type), визначені [види](./glossary.md#glossary-view) і т.д. Дивіться [understanding-data](./understanding-data.md) для додаткової інформації.

## Користувач { #glossary-user }

Особа, яка взаємодіє з сайтом, здійснивши вхід або [анонімно](./glossary.md#glossary-anonymous). Дивіться [user-concept](./user-concept.md) для додаткової інформації.

## Крон { #glossary-cron }

В деяких операційних системах, _крон_ це додаток планувальника команд, що виконує команди або сценарії періодично. Ваш сайт визначає періодичність завдань, також відомих як крон-завдань, які мають бути виконані або за допомогою крон-планувальника або внутрішніми засобами. Дивіться [security-cron-concept](./security-cron-concept.md) для додаткової інформації.

## Майстер { #glossary-wizard }

Веб-форма, яка дає можливість заповнити декілька значень і створює щось вагоме відштовхуючись від даних що ви вказали. Наприклад, є майстри для створення [видів](./glossary.md#glossary-view) різних типів. Дивіться [views-create](./views-create.md) для додаткової інформації.

## Матеріал { #glossary-content-item }

Одиниця [вмісту](./glossary.md#glossary-content), що як правило відображається в якості головного вмісту на сторінці вашого сайту. Представляє собою [тип сутності](./glossary.md#glossary-entity-type). Дивіться [planning-data-types](./planning-data-types.md) для додаткової інформації.

## Меню { #glossary-menu }

Набір посилань, які використовуються для навігації по сайту, можуть бути відсортовані в деревовидному порядку. Дивіться [menu-concept](./menu-concept.md) для додаткової інформації.

## Модуль { #glossary-module }

Програмне забезпечення (зазвичай PHP, JavaScript, та/або CSS) що розширює можливості сайту та додає функціональність. Drupal розрізняє _[ядро](./glossary.md#glossary-drupal-core)_ та _[внесені](./glossary.md#glossary-contributed)_ модулі. Дивіться [understanding-modules](./understanding-modules.md) для додаткової інформації.

## Оновлення { #glossary-update }

Нова версія програмного забезпечення вашого сайту, [ядро Drupal](./glossary.md#glossary-drupal-core), [модуль](./glossary.md#glossary-module) або [тема](./glossary.md#glossary-theme). Дивіться також [оновлення безпеки](./glossary.md#glossary-security-update). Дивіться [security-concept](./security-concept.md) для додаткової інформації.

## Оновлення безпеки { #glossary-security-update }

[Оновлення](./glossary.md#glossary-update) що виправляє помилку безпеки, наприклад вразливі місця для зловмисників. Дивіться [security-concept](./security-concept.md) для додаткової інформації.

## Пакет { #glossary-bundle }

Синонім для [Підтип сутності](./glossary.md#glossary-entity-subtype).

## Пакет поля { #glossary-field-bundle }

Синонім для [Підтип сутності](./glossary.md#glossary-entity-subtype).

## Перший користувач (Користувач 1) { #glossary-user-one }

Обліковий запис початкового [користувача](./glossary.md#glossary-user), який було створено під час інсталяції сайту (ідентифікаційний номер якого дорівнює 1). Цей користувач автоматично має всі [дозволи](./glossary.md#glossary-permission), навіть якщо йому не призначено адміністративну [роль](./glossary.md#glossary-role). Дивіться [user-admin-account](./user-admin-account.md) для додаткової інформації.

## Підтип сутності { #glossary-entity-subtype }

В межах [матеріалу](./glossary.md#glossary-content) [тип сутності](./glossary.md#glossary-entity-type), групування сутностей, що мають спільні [поля](./glossary.md#glossary-field). Наприклад, в межах типу сутності [одиниці матеріалу](./glossary.md#glossary-content-item), сайт фермерського ярмарку може мати підтипи (відомі як [типи матеріалу](./glossary.md#glossary-content-type)) для статичних сторінок і сторінок продавців, кожен зі своєю власною групою полів. Ви також можете зустріти термін _пакет_, який використовується (особливо в програмній документації) як синонім до підтипу сутності. Дивіться [planning-data-types](./planning-data-types.md) для додаткової інформації.

## Поле { #glossary-field }

Дані певного типу, який прикріплений до [сутності](./glossary.md#glossary-entity) [матеріалу](./glossary.md#glossary-content). Наприклад тип матеріалу "Продавець", на сайті фермерського ярмарку, може мати поля для зображення, опису продавця, та [терміну таксономії](./glossary.md#glossary-taxonomy-term). Дивіться [planning-data-types](./planning-data-types.md) для додаткової інформації.

## Поле-посилання { #glossary-reference-field }

[Поле](./glossary.md#glossary-field) що представляє зв'язок між [сутністю](./glossary.md#glossary-entity) та одною або або більше сутностей, які можуть мати однаковий [тип сутності](./glossary.md#glossary-entity-type) або різних типів. Наприклад, на сайті фермерського ярмарку, матеріал рецепт може містити поле посилання на продавця (також матеріал), який розмістив рецепт. Поля [термінів таксономії](./glossary.md#glossary-taxonomy-term) є також полями посиланнями. Дивіться [structure-reference-fields](./structure-reference-fields.md) для додаткової інформації.

## Регіон { #glossary-region }

Визначена область сторінки де може бути розміщений [вміст](./glossary.md#glossary-content), такий як верхній або нижній колонтитул, головна область матеріалів, ліва колонка і т.д. Регіони визначені [темами](./glossary.md#glossary-theme), і вміст відображений в кожному регіоні міститься в [блоках](./glossary.md#glossary-block). Дивіться [block-regions](./block-regions.md) для додаткової інформації.

## Редакція { #glossary-revision }

Запис минулого або поточного стану [сутності](./glossary.md#glossary-entity) [матеріалу](./glossary.md#glossary-content), що редагується через деякий час. Дивіться [planning-workflow](./planning-workflow.md) для додаткової інформації.

## Режим перегляду { #glossary-view-mode }

Набір [конфігурації](./glossary.md#glossary-configuration) [форматерів](./glossary.md#glossary-field-formatter) для всіх [полів](./glossary.md#glossary-field) [сутності](./glossary.md#glossary-entity) [матеріалу](./glossary.md#glossary-content), деякі з них можуть бути приховані. Кожний [підтип сутності](./glossary.md#glossary-entity-subtype) може мати один або декілька визначених режимів перегляду; наприклад, [тип матеріалу](./glossary.md#glossary-content-type) зазвичай має _Повний_ та _Анонс_ режим перегляду, де _Анонс_ режим перегляду відображає зменшені або обрізані значення полів. Дивіться [structure-view-modes](./structure-view-modes.md) для додаткової інформації.

## Роль { #glossary-role }

Назва набору [дозволів](./glossary.md#glossary-permission), які можуть бути застосовані до облікового запису [користувача](./glossary.md#glossary-user). Дивіться [user-concept](./user-concept.md) для додаткової інформації.

## Синонім { #glossary-alias }

Зрозуміла користувачу назва, що замінює внутрішній [шлях](./glossary.md#glossary-path) який система призначає в якості URL на сайті. Наприклад, ви можете призначити синонім _/about_ для сторінка "Про нас" на вашому сайті, щоб замінити внутрішній шлях _/node/5_. В такому разі ви отримуєте сторінку з URL _http://example.com/about_ замість _http://example.com/node/5_. Дивіться [content-paths](./content-paths.md) для додаткової інформації.

## Система керування вмістом (СКВ) { #glossary-content-management-system }

Збірка інструментів, призначених для забезпечення можливості створення, редагування, організації, пошуку, виправлення, видалення інформації на веб-сайті. Дивіться [understanding-drupal](./understanding-drupal.md) для додаткової інформації.

## СКВ { #glossary-cms }

Акронім для [Система керування вмістом](./glossary.md#glossary-content-management-system).

## Словник { #glossary-vocabulary }

Група [термінів таксономії](./glossary.md#glossary-taxonomy-term), які обираються під час сортування [матеріалу](./glossary.md#glossary-content) певним шляхом, наприклад перелік всіх категорій продавців на фермерському сайті. Технічно, словники це [підтип сутності](./glossary.md#glossary-entity-subtype) для [типу сутності](./glossary.md#glossary-entity-type) терміну таксономії. Дивіться [structure-taxonomy](./structure-taxonomy.md) для додаткової інформації.

## Стан { #glossary-state }

Інформація тимчасового характеру про поточний стан вашого сайту, така як час останнього запуску [крон](./glossary.md#glossary-cron) і т.д. Дивіться також [матеріал](./glossary.md#glossary-content) та [конфігурація](./glossary.md#glossary-configuration). Дивіться [understanding-data](./understanding-data.md) для додаткової інформації.

## Стиль зображення { #glossary-image-style }

Набір кроків обробки, що перетворює базове зображення у нове зображення; зазвичай обробка включає в себе масштабування і кадрування. Дивіться [structure-image-styles](./structure-image-styles.md) для додаткової інформації.

## Сутність { #glossary-entity }

Елемент будь-якого [матеріалу](./glossary.md#glossary-content) або [конфігурація](./glossary.md#glossary-configuration) даних, хоча в загальному користуванні, цей термін часто повз'язується сутностями матеріалу. Приклади включають в себе [матеріали](./glossary.md#glossary-content-item), власні [блоки](./glossary.md#glossary-block), [терміни таксономії](./glossary.md#glossary-taxonomy-term), і визначення [типів матеріалу](./glossary.md#glossary-content-type); Перші три є сутностями матеріалу, а остання є сутністю конфігурації. Дивіться також [Тип сутності](./glossary.md#glossary-entity-type), [Підтип сутності](./glossary.md#glossary-entity-subtype), та [Поле](./glossary.md#glossary-field). Дивіться [planning-data-types](./planning-data-types.md) для додаткової інформації.

## Текстовий формат { #glossary-text-format }

[Конфігурація](./glossary.md#glossary-configuration) що визначає обробку, що відбувається з вмістом що вводить користувач перед тим, як він буде показаний у браузері. Процес може містити вилучення або обмеження на використання HTML-тегів, або перетворювати URL у посилання. Дивіться [structure-text-formats](./structure-text-formats.md) для додаткової інформації.

## Тема { #glossary-theme }

Програмне забезпечення та файли (зображення, CSS-, PHP-код та/або шаблони) що визначають стилі або схему сайту. Drupal відрізняє теми, які є частиною _[ядра](./glossary.md#glossary-drupal-core)_ і які є _[внесеними](./glossary.md#glossary-contributed)_ темами. Дивіться [understanding-themes](./understanding-themes.md) для додаткової інформації.

## Термін таксономії { #glossary-taxonomy-term }

Термін, що використовується для класифікації [матеріалу](./glossary.md#glossary-content), такий як тег або категорія. Дивіться також [Словник](./glossary.md#glossary-vocabulary). Дивіться [structure-taxonomy](./structure-taxonomy.md) для додаткової інформації. продавців. Дивіться [planning-data-types](./planning-data-types.md) для додаткової інформації.

## Тип матеріалу { #glossary-content-type }

[Підтип сутності](./glossary.md#glossary-entity-subtype) для [типу сутності](./glossary.md#glossary-entity-type) [матеріал](./glossary.md#glossary-content-item). Кожен тип матеріалу використовується для деяких конкретних цілей на сайті, кожен має свої власні поля. Наприклад, сайт для фермерського ярмарку може мати тип матеріалу для простої сторінки, та інший для сторінки з переліком продавців. Дивіться [planning-data-types](./planning-data-types.md) для додаткової інформації.

## Тип сутності { #glossary-entity-type }

Загальний тип [сутності](./glossary.md#glossary-entity); в загальному користуванні, вона застосовується тільки до сутностей [матеріалу](./glossary.md#glossary-content). Приклади включають в себе [типи матеріалу](./glossary.md#glossary-content-type), [терміни таксономії](./glossary.md#glossary-taxonomy-term), і власні [блоки](./glossary.md#glossary-block). Дивіться [planning-data-types](./planning-data-types.md) для додаткової інформації.

## Точка переходу { #glossary-breakpoint }

Точки переходу використовуються для розділення висоти або ширини екрану браузера, області друку принтера, та інших типів медіа відображення на кроки. [Адаптивний](./glossary.md#glossary-responsive) сайт коректує відображення під ці точки переходу. Дивіться [structure-image-responsive](./structure-image-responsive.md) для додаткової інформації.

## Форматер поля { #glossary-field-formatter }

[Конфігурація](./glossary.md#glossary-configuration), що визначає, як будуть відображатися дані [поля](./glossary.md#glossary-field) . Наприклад, текстове поле може бути відображене з префіксом та/або суфіксом, поле може обмеження на виведення HTML-тегів або заборону. Дивіться [Режим перегляду](./glossary.md#glossary-view-mode) та [Віджет поля](./glossary.md#glossary-field-widget). Дивіться [structure-view-modes](./structure-view-modes.md) для додаткової інформації.

## Шлях { #glossary-path }

Унікальна, остання частина внутрішнього URL, що система призначає для сторінки сайту, яка може бути як сторінкою для відвідувачів так і адміністративною сторінкою. Наприклад, внутрішній URL сторінки "Про нас" на вашому сайті може бути _http://example.com/node/5_, і в цьому випадку, шлях буде _node/5_. Дивіться також [Синонім](./glossary.md#glossary-alias). Дивіться [content-paths](./content-paths.md) для додаткової інформації.
