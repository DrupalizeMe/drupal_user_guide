# AsciiDoc → Markdown migration pipeline

The tooling, and this documentation, was authored with Claude Code.

Tooling that converts the guide's AsciiDoc sources (`source/<locale>/*.asciidoc`)
into the committed Markdown under `content/<locale>/docs/`, for
[issue #3470837](https://www.drupal.org/project/user_guide/issues/3470837).

The conversion is scripted and deterministic so that anyone can re-run it and get
the same result.

## Requirements

- Node.js (tested on v24)
- Python 3 with PyYAML
- `source/<locale>/` present in the working tree

## Running it

```bash
node scripts/migrate/convert-all.mjs              # all locales, stage 1
node scripts/migrate/convert-locale.mjs es        # one locale, stage 1
python3 scripts/migrate/normalize_docs.py         # all locales, stage 3
python3 scripts/migrate/normalize_docs.py es id   # specific locales, stage 3
```

## Pipeline stages

### Stage 1 — `convert-locale.mjs` (+ `convert-all.mjs`, `guide-structure.mjs`)

Reads `source/<locale>/*.asciidoc` and writes Markdown to `content/<locale>/docs/`,
copying screenshots to `content/<locale>/docs/images/`.

Ordering and chapter grouping come from `guide-structure/<locale>.mjs`.

### Stage 2 — nav and landing pages: **superseded**

Each locale's `zensical.toml` and `index.md` were initially generated by a script.
Going forward, update them by hand as needed.

### Stage 3 — `normalize_docs.py` (+ `normalize_shared.py`)

Rewrites stage 1's output into the shape the committed content uses:

- `<a id="x"></a>` + heading → `## Heading { #x }`; bare `<a id="x"></a>` → `[](){ #x }`
- resolves legacy `<<id>>` references into placeholder Markdown links
- normalizes inline `.md` link labels to the target's filename stem
- converts indented AsciiDoc tables
- collapses runs of blank lines
- removes leftovers from an earlier Astro-based version of the site

## The link model

Committed content stores **placeholder links** whose label is the target's own
filename stem:

```markdown
See [content-create](./content-create.md).
```

The human-readable title is substituted at **build time** by
`scripts/zensical/site_prep.py::normalize_placeholder_links`, which maps filename →
frontmatter title. Keeping titles out of the committed source means retitling a page
doesn't require editing every page that links to it.

Anchored links (`./glossary.md#glossary-path`) keep whatever label the AsciiDoc
source gave them and are left untouched.

## Syncing upstream changes

To port upstream AsciiDoc changes for a locale, update `source/<locale>/`, run
stages 1 and 3 for that locale, and review `git diff content/<locale>`. Differences
should be the upstream changes. Watch for:

- **Nav changes.** If `source/<locale>/guide.asciidoc` changes, add, remove, or
  reorder entries in `content/<locale>/zensical.toml` by hand.
- **Deleted topics.** The converter only writes files for sources that exist, so a
  topic deleted upstream leaves its old Markdown file behind. Delete it by hand.
- **Unresolved links.** Links to topics that don't exist in that locale are written
  as `#unresolved-<id>` links. Remove or fix them by hand.

## Known gap

There is no parser for `guide.asciidoc`. The per-locale files in `guide-structure/`
were generated once during the original migration and committed as data. That's why
upstream changes to a locale's `guide.asciidoc` have to be reconciled by hand, and
why `guide-structure/<locale>.mjs` can lag behind current upstream.
