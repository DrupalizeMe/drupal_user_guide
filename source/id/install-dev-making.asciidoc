=== Membuat Situs Pengembangan

[role="summary"]
Cara membuat salinan situs aktif untuk tujuan pengembangan.

(((Situs pengembangan,membuat)))
(((Situs staging,membuat)))

==== Tujuan

Buat salinan situs yang dapat Anda gunakan untuk mengembangkan fitur baru dan
menguji pembaruan.

==== Pengetahuan prasyarat

<<install-dev-sites>>

==== Prasyarat situs

* Anda memiliki situs aktif yang telah dikembangkan dan ingin Anda salin untuk
tujuan pengembangan.

* Jika ingin menggunakan Drush untuk beberapa langkah dalam tugas ini, Drush
harus diinstal. Lihat <<install-tools>>.

* Jika ingin menggunakan DDEV untuk lingkungan lokal Anda, ikuti langkah-langkah
di <<install-ddev>>. Kemudian, ikuti petunjuk di bagian khusus DDEV di bawah.

==== Langkah umum untuk membuat situs pengembangan

. Ikuti langkah-langkah di <<install-prepare>>, sehingga hosting untuk situs
  pengembangan Anda telah disiapkan, Anda mengetahui lokasi root web situs
  pengembangan, dan Anda memiliki basis data kosong serta pengguna basis data
  untuk digunakan oleh situs pengembangan.

. Langkah berikutnya adalah membuat berkas dump basis data, yang berisi isi
  basis data situs Anda. Berkas ini dapat berukuran cukup besar, tetapi ada dua
  hal yang dapat dilakukan untuk mengurangi ukurannya:
+
  * Kompres berkas menggunakan gzip atau utilitas kompresi lainnya.
  * Kecualikan isi tabel basis data untuk sistem cache internal dengan
  mengosongkan tabel-tabel tersebut. Datanya bersifat sementara, dan Anda hanya
  memerlukan struktur tabel, bukan isi tabel, untuk membuat salinan situs.
+
Untuk membuat dump basis data, cobalah salah satu metode berikut:
+
  * Jika menggunakan Drush, gunakan perintah ini, yang hanya akan menyertakan
  struktur dan bukan isi tabel cache, serta mengompres output dengan gzip:
+
----
drush sql:dump --gzip --structure-tables-list="cache,cache_*" \
  --result-file='PATH/TO/BACKUPFILE.sql'
----
+
  * Jika menggunakan MySQL dan memiliki akses ke baris perintah, gunakan
  perintah ini setelah mengosongkan tabel cache (gantikan dengan nama basis
  data, nama pengguna, dan kata sandi situs Anda):
+
----
mysqldump -u'USERNAME' -p'PASSWORD' DATABASENAME | \
  gzip > PATH/TO/BACKUPFILE.sql.gz
----

  * Jika menggunakan MySQL sebagai basis data dan server situs aktif Anda
  memasang phpMyAdmin (tersedia dari banyak panel kontrol hosting), Anda dapat
  mengosongkan tabel cache dengan memilihnya dalam daftar struktur tabel
  phpMyAdmin dan memilih operasi _Empty_ di bagian bawah halaman. Kemudian,
  gunakan tab _Export_ di phpMyAdmin untuk mengekspor dalam format _SQL_, dengan
  kompresi _gzip_ untuk mengurangi ukuran berkas.

  * Gunakan
  https://www.drupal.org/project/backup_migrate[modul Backup and Migrate kontribusi]
  dari dalam situs aktif Anda. Lihat <<extend-module-install>> untuk petunjuk
  menginstal modul kontribusi.
+
Kini Anda memiliki dump basis data yang disimpan dalam berkas
_BACKUPFILE.sql.gz_. Demi alasan keamanan, hindari menyimpan berkas ini di
server hosting Anda di lokasi mana pun di bawah root situs Drupal. Ini akan
mencegah orang lain mendapatkan salinan basis data Anda.

. Salin semua berkas dari root web situs aktif ke root web situs pengembangan.
  Anda mungkin ingin menggunakan Git untuk melakukannya; jika demikian, lihat
  <<extend-git>>.

. Edit berkas _sites/default/settings.php_ di bawah direktori tingkat teratas
  situs pengembangan dalam editor teks biasa. Temukan baris di dekat akhir yang
  berisi nama basis data, nama pengguna basis data, dan kata sandi basis data,
  lalu perbarui dengan informasi basis data situs pengembangan yang telah Anda
  siapkan. Baris-baris tersebut tampak seperti ini (sebelum diedit):
+
----
$databases['default']['default'] = [
  'database' => 'live_site_database_name',
  'username' => 'live_site_database_username',
  'password' => 'live_site_database_password',
  …
----

. Periksa apakah berkas _settings.php_ Anda memiliki pengaturan berikut; jika
  ya, Anda perlu mengeditnya agar mengarah ke URL situs pengembangan alih-alih
  URL situs produksi:
+
----
$settings['trusted_host_patterns']
----

. Periksa apakah berkas _settings.php_ Anda memiliki pengaturan berikut dan
  diatur ke nilai string acak. Jika tidak, Anda perlu menambahkannya atau
  mengeditnya untuk mencegah kesalahan fatal:
+
--
----
$settings['hash_salt'] = 'any_string_value';
----

Salah satu cara menghasilkan string acak untuk hash salt adalah perintah Drush
berikut:

----
drush php-eval 'echo
  \Drupal\Component\Utility\Crypt::randomBytesBase64(55) . "\n";'
----

Jika tidak menggunakan Drush, ada banyak situs web dan aplikasi yang
menyediakan generator string acak; Anda perlu menghasilkan string dengan
panjang sekitar 74 karakter.
--

. Impor berkas dump basis data yang Anda buat ke basis data situs pengembangan.
  Cobalah salah satu metode berikut:
+
  * Jika menggunakan MySQL sebagai basis data dan server situs aktif Anda
  memasang phpMyAdmin (tersedia dari banyak panel kontrol hosting), gunakan tab
  _Import_ di phpMyAdmin. Anda mungkin perlu memulai ulang impor beberapa kali
  jika basis data Anda besar.

  * Jika menggunakan MySQL dan memiliki akses ke baris perintah, gunakan
  perintah ini (gantikan dengan nama basis data, nama pengguna, dan kata sandi
  situs Anda; jika membuat berkas cadangan yang dikompres gzip, Anda juga perlu
  mengekstraknya terlebih dahulu):
+
----
gunzip < PATH/TO/BACKUPFILE.sql.gz | \
  mysql -u'USERNAME' -p'PASSWORD' DATABASENAME
----
+
  * Jika lebih suka menggunakan Drush, gunakan perintah ini:
+
----
drush sql:query --file='PATH/TO/BACKUPFILE.sql.gz'
----

. Jika situs pengembangan dan situs aktif Anda memerlukan konfigurasi yang
  berbeda, Anda harus menggunakan override konfigurasi dalam berkas
  _settings.php_. Variabel _$config_ membantu Anda mempertahankan nilai override
  secara terpisah dari data konfigurasi standar. Misalnya, Anda mungkin ingin
  nama situs menjadi "Anytown Farmers Market" di situs produksi, tetapi
  "Development Site for Anytown Farmers Market" di situs pengembangan. Untuk
  melakukannya, Anda dapat memiliki nilai produksi dalam konfigurasi situs
  (dalam basis data), dan di situs pengembangan, dalam berkas settings.php,
  Anda perlu memiliki:
+
----
$config['system.site']['name'] =
  "Development Site for Anytown Farmers Market";
----

==== Langkah khusus DDEV untuk membuat situs pengembangan

. Di direktori tempat Anda menyalin semua berkas dari situs aktif, jalankan
  perintah berikut untuk mengonfigurasi dan memulai lingkungan DDEV:
+
----
ddev config --project-type=drupal11 --docroot=web
ddev start
----
+
Ini mengasumsikan bahwa Anda menggunakan struktur direktori yang
direkomendasikan dengan root web berada dalam subdirektori bernama _web_. Jika
menggunakan struktur direktori berbeda, Anda perlu menyesuaikan opsi
_--docroot_.

. Gunakan perintah berikut untuk mengimpor berkas dump basis data yang Anda
  buat:
+
----
ddev import-db --file=PATH/TO/BACKUPFILE.sql.gz
----

==== Perdalam pemahaman Anda

* Pastikan situs pengembangan berfungsi dengan benar.

* Masuk ke situs pengembangan sebagai administrator, lalu kosongkan cache.
Lihat <<prevent-cache-clear>>.
