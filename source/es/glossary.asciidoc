[[glossary]]
== Glosario

(((Glosario)))
(((Terminología (Glosario))))

(((Ajax,definición)))
[glossary]
[[glossary-ajax]] Ajax::
   Tecnología web usada para intercambiar datos con un servidor y actualizar
   dinámicamente partes de una página web (por ejemplo, formularios) sin
   necesidad de recargar la página entera.
(((Alias,definición)))
[[glossary-alias]] Alias::
   Nombre fácil de recordar que reemplaza a la <<glossary-path,path>> interna
   que el sistema asigna a una <<glossary-url,URL>> del sitio. Por ejemplo,
   podría asignar el alias _/about_ a la página Acerca de de su sitio para
   reemplazar la ruta interna _/node/5_. Esto daría a la página la URL
   _http://example.com/about_ en lugar de _http://example.com/node/5_. Consultar
   <<content-paths>> para más información.
(((Anónimo,definición)))
[[glossary-anonymous]] Anónimo::
   Persona (<<glossary-user,user>>) que interactúa con el sitio sin haber
   iniciado sesión. Consultar <<user-concept>> para más información.
(((Autenticado,definición)))
[[glossary-authenticated]] Autenticado::
   Persona (<<glossary-user,user>>) que interactúa con el sitio habiendo
   iniciado sesión. Consultar <<user-concept>> para más información.
(((Bloque,definición)))
[[glossary-block]] Bloque::
   Fragmento de <<glossary-content,content>> (texto, imágenes, enlaces, etc.)
   que se puede mostrar en una página de un sitio. Los bloques se muestran en
   <<glossary-region,regions>>. Consultar <<block-concept>> para más
   información.
(((Breakpoint,definición)))
[[glossary-breakpoint]] Breakpoint::
   Los breakpoints se usan para separar en pasos la altura o la anchura de las
   pantallas de los navegadores, las impresoras y otros tipos de salida. Un
   sitio <<glossary-responsive,responsive>> ajusta su presentación en estos
   breakpoints. Consultar <<structure-image-responsive>> para más información.
(((Bundle,definición)))
[[glossary-bundle]] Bundle::
   Sinónimo de <<glossary-entity-subtype,Entity subtype>>.
(((Caché,definición)))
[[glossary-cache]] Caché::
   La caché interna del sitio almacena la salida de cálculos costosos, como
   generar la salida de una petición de página HTML, y luego la recupera en
   lugar de recalcularla la siguiente vez que se necesita. También se pueden
   usar sistemas de caché externos en el servidor web para acelerar la
   respuesta de un sitio. Consultar <<prevent-cache>> para más información sobre
   la caché interna.
(((Coder,definición)))
[[glossary-coder]] Coding standards::
   Los estándares de código (coding standards) son las reglas para los
   programadores que definen buenas prácticas, formato y otras normas, de modo
   que todo el mundo use las mismas convenciones y tenga las mismas expectativas
   al ver el código. Consultar <<install-tools>> para más información.
(((Composer,definición)))
[[glossary-composer]] Composer::
   El gestor de dependencias de PHP que usan Drupal, <<glossary-drush, Drush>>,
   el framework Symfony y otros. Es la forma preferida de instalar proyectos de
   Drupal. Consultar <<install-composer>> para más información.
(((CMS (Sistema de gestión de contenidos),definición)))
(((Sistema de gestión de contenidos (CMS),definición)))
[[glossary-cms]] CMS::
   Acrónimo de
   <<glossary-content-management-system,Content Management System>>.
(((Configuración,definición)))
[[glossary-configuration]] Configuración::
   Información sobre su sitio que no es <<glossary-content,content>> y que está
   pensada para ser más permanente que la información de
   <<glossary-state,state>>, como el nombre de su sitio, los
   <<glossary-content-type,content types>> y las <<glossary-view,views>> que ha
   definido, etc. Consultar <<understanding-data>> para más información.
(((Contenido,definición)))
[[glossary-content]] Contenido::
   Información pensada para mostrarse en su sitio, como texto, imágenes,
   descargas, etc. Véase también <<glossary-configuration,Configuration>> y
   <<glossary-state,State>>. Consultar <<understanding-data>> para más
   información.
(((Elemento de contenido,definición)))
[[glossary-content-item]] Content item::
   Elemento de <<glossary-content,content>> que normalmente está pensado para
   mostrarse como el contenido principal de una página de su sitio. Es un
   <<glossary-entity-type,entity type>>. Consultar <<planning-data-types>> para
   más información.
(((Sistema de gestión de contenidos (CMS),definición)))
[[glossary-content-management-system]] Content Management System (CMS)::
   Conjunto de herramientas diseñadas para permitir la creación, modificación,
   organización, búsqueda, recuperación y eliminación de información en un sitio
   web. Consultar <<understanding-drupal>> para más información.
(((Tipo de contenido,definición)))
[[glossary-content-type]] Content type::
   Un <<glossary-entity-subtype,entity subtype>> para el
   <<glossary-entity-type,entity type>> <<glossary-content-item,content item>>.
   Cada tipo de contenido se usa con un propósito concreto en el sitio y cada
   uno tiene sus propios campos. Por ejemplo, un sitio para un mercado de
   agricultores podría tener un tipo de contenido para páginas sencillas y otro
   para una página de listado de proveedores. Consultar <<planning-data-types>>
   para más información.
(((Filtro contextual,definición)))
[[glossary-contextual-filter]] Contextual Filter (in a View)::
  Limita los datos que va a mostrar una <<glossary-view, view>> en función del
  contexto del <<glossary-display, display>> de la vista, como la URL completa
  de la página. Consultar <<views-parts>> para más información.
(((Enlace contextual,definición)))
[[glossary-contextual-link]] Enlace contextual::
   Enlace a una página de administración para editar o configurar una
   funcionalidad del sitio, que se muestra en el contexto donde aparece esa
   funcionalidad. Ejemplo: un enlace para configurar un <<glossary-menu,menu>>
   que se muestra al pasar el ratón por encima del menú. Consultar
   <<config-overview>> para más información.
(((Contribuido,definición)))
(((Módulo contribuido,definición)))
(((Tema contribuido,definición)))
[[glossary-contributed]] Contribuido::
   <<glossary-module,Modules>>, <<glossary-theme,themes>> y
   <<glossary-distribution,distributions>> que no forman parte de la descarga
   del <<glossary-drupal-core,Drupal core>> y que se pueden descargar por
   separado desde el sitio web https://www.drupal.org[_Drupal.org_].
(((Tarea de cron,definición)))
(((Planificador de comandos cron,definición)))
[[glossary-cron]] Cron::
   En algunos sistemas operativos, _cron_ es una aplicación planificadora de
   comandos que ejecuta comandos o scripts periódicamente. Su sitio define
   tareas periódicas, también conocidas como tareas de cron, que deben lanzarse
   mediante un planificador cron del sistema operativo o internamente. Consultar
   <<security-cron-concept>> para más información.
(((Cross Site Scripting (XSS),definición)))
[[glossary-cross-site-scripting]] Cross Site Scripting::
   Vulnerabilidad de seguridad habitual en los sitios web. En un sitio que no
   está bien protegido, un usuario malicioso puede introducir código de script
   en páginas web que otros usuarios visualizan. Consultar
   <<structure-text-formats>> para más información.
(((Devel,definición)))
[[glossary-devel]] Devel::
   Módulo que ayuda con tareas de desarrollo como depurar e inspeccionar
   código, analizar consultas a la base de datos y generar contenido de prueba.
   Consultar <<install-tools>> para más información.
(((Entorno de desarrollo,definición)))
[[glossary-development-site]] Development site::
   Copia del sitio en producción que se usa para desarrollar, actualizar y
   probar el sitio. Consultar <<install-dev-sites>> para más información.
(((Display,definición)))
[[glossary-display]] Display (in a View)::
  Tipo de salida de una <<glossary-view, view>>, por ejemplo una página, un
  <<glossary-block, block>> o un feed. Consultar <<views-parts>> para más
  información.
(((Distribución,definición)))
[[glossary-distribution]] Distribución::
   Descarga única que proporciona un atajo para configurar un tipo concreto de
   sitio, como un sitio web para un club o para comercio electrónico. Una
   distribución contiene el <<glossary-drupal-core,Drupal core>>, junto con
   <<glossary-contributed,contributed>> <<glossary-module,modules>> y/o
   <<glossary-theme,themes>>; muchas distribuciones también preconfiguran el
   sitio o incluso crean contenido de ejemplo durante la
   <<glossary-installing,installation>>. Consultar
   <<understanding-distributions>> para más información.
(((Drupal Association (DA),definición)))
(((DA (Drupal Association),definición)))
[[glossary-drupal-association]] Drupal Association::
   Organización sin ánimo de lucro dedicada a apoyar el proyecto y la comunidad
   Drupal. Consultar <<understanding-project>> para más información.
(((Núcleo de Drupal,definición)))
[[glossary-drupal-core]] Drupal core::
   Los archivos, temas, perfiles y módulos que se incluyen en la descarga
   estándar del software del proyecto. Consultar <<understanding-drupal>> para
   más información.
(((Drush,definición)))
[[glossary-drush]] Drush::
  Shell de línea de comandos e interfaz de scripting para Drupal. Consultar
  <<install-tools>> para más información.
(((Flujo de trabajo editorial,definición)))
[[glossary-editorial-workflow]] Editorial Workflow::
   Proceso para crear, revisar, editar y publicar contenido. En el proceso
   pueden participar varias personas con distintos roles (por ejemplo, quienes
   crean el contenido y quienes lo editan). Consultar <<planning-workflow>> para
   más información.
(((Entidad,definición)))
[[glossary-entity]] Entidad::
   Elemento de datos de <<glossary-content,content>> o de
   <<glossary-configuration,configuration>>, aunque en el uso habitual el
   término suele referirse a las entidades de contenido. Algunos ejemplos son
   los <<glossary-content-item,content items>>, los <<glossary-block,blocks>>
   personalizados, los <<glossary-taxonomy-term,taxonomy terms>> y las
   definiciones de <<glossary-content-type,content types>>; los tres primeros
   son entidades de contenido y la última es una entidad de configuración.
   Véase también <<glossary-entity-type,Entity type>>,
   <<glossary-entity-subtype,Entity subtype>> y <<glossary-field,Field>>.
   Consultar <<planning-data-types>> para más información.
(((Subtipo de entidad,definición)))
[[glossary-entity-subtype]] Entity subtype::
   Dentro de un <<glossary-entity-type,entity type>> de
   <<glossary-content,content>>, agrupación de entidades que comparten los
   mismos <<glossary-field,fields>>. Por ejemplo, dentro del entity type
   <<glossary-content-item,content item>>, un sitio de mercado de agricultores
   podría tener subtipos (conocidos como <<glossary-content-type,content
   types>>) para páginas estáticas y páginas de proveedores, cada uno con su
   propio grupo de campos. También puede encontrar el término _bundle_
   (especialmente en la documentación para programadores) como sinónimo de
   subtipo de entidad. Consultar <<planning-data-types>> para más información.
(((Tipo de entidad,definición)))
[[glossary-entity-type]] Entity type::
   El tipo general de una <<glossary-entity,entity>>; en el uso habitual, solo
   se aplica a una entidad de <<glossary-content,content>>. Algunos ejemplos son
   los <<glossary-content-type,content types>>, los
   <<glossary-taxonomy-term,taxonomy terms>> y los <<glossary-block,blocks>>
   personalizados. Consultar <<planning-data-types>> para más información.
(((Campo,definición)))
[[glossary-field]] Campo::
   Datos de un cierto tipo que se adjuntan a una <<glossary-entity,entity>> de
   <<glossary-content,content>>. Por ejemplo, en el tipo de contenido de
   proveedor de un sitio de mercado de agricultores, podría tener campos para
   una imagen, la descripción del proveedor y un
   <<glossary-taxonomy-term,taxonomy term>>. Consultar <<planning-data-types>>
   para más información.
(((Field bundle,definición)))
[[glossary-field-bundle]] Field bundle::
   Sinónimo de <<glossary-entity-subtype,Entity subtype>>.
(((Formateador,definición)))
(((Formateador de campo,definición)))
[[glossary-field-formatter]] Field formatter::
   <<glossary-configuration,Configuration>> que define cómo se muestran los
   datos de un <<glossary-field,field>>. Por ejemplo, un campo de texto se
   podría mostrar con un prefijo o un sufijo, y se le podrían eliminar o limitar
   sus etiquetas HTML. Véase también <<glossary-view-mode,View mode>> y
   <<glossary-field-widget,Field widget>>. Consultar <<structure-view-modes>>
   para más información.
(((Widget,definición)))
(((Widget de campo,definición)))
[[glossary-field-widget]] Field widget::
   <<glossary-configuration,Configuration>> que define cómo se introducen o
   editan los datos de un <<glossary-field,field>> en un formulario de entrada
   de datos. Por ejemplo, un campo de texto podría usar una caja de entrada de
   una línea o de varias líneas, y podría haber un ajuste para el tamaño de la
   caja. Véase también <<glossary-field-formatter,Field formatter>>. Consultar
   <<structure-widgets>> para más información.
(((Filtro,definición)))
[[glossary-filter]] Filter (in a View)::
  Limita los datos que va a mostrar una <<glossary-view, view>> en función de
  criterios como el estado de publicación, el tipo de contenido o el valor de
  un campo. Consultar <<views-parts>> para más información.
[[glossary-formatter]] Formatter::
   Consultar <<glossary-field-formatter,Field formatter>>.
(((FOSS (Free and Open Source Software),definición)))
(((Free and Open Source Software (FOSS),definición)))
[[glossary-foss]] FOSS::
   Acrónimo de _Free and Open Source Software_ (software libre y de código
   abierto), que hace referencia al software desarrollado por una comunidad de
   personas y publicado bajo una licencia no comercial. Véase también
   <<glossary-gpl,GPL>>. Consultar <<understanding-project>> para más
   información.
(((Git,definición)))
[[glossary-git]] Git::
  <<glossary-vcs, Sistema de control de versiones>> que usan las personas que
  desarrollan Drupal para coordinar sus cambios de código individuales. Git
  registra los cambios de todo el mundo en un proyecto dado en un árbol de
  directorios llamado <<glossary-repository, repository>> de git. Consultar
  <<install-tools>> para más información.
(((GPL (Licencia Pública General o Licencia Pública General de GNU),definición)))
(((Licencia Pública General de GNU,definición)))
[[glossary-gpl]] GPL::
   Acrónimo de _GNU General Public License_ (Licencia Pública General de GNU),
   una licencia de software no comercial. Todo el software descargado desde el
   sitio web https://www.drupal.org[_Drupal.org_] está licenciado bajo la
   http://www.gnu.org/licenses/old-licenses/gpl-2.0.html["GNU General Public
   License, version 2"]. Véase también <<glossary-foss,FOSS>>. Consultar
   <<understanding-gpl>> para más información.
(((Estilo de imagen,definición)))
[[glossary-image-style]] Image style::
   Conjunto de pasos de procesamiento que transforman una imagen base en una
   imagen nueva; el procesamiento típico incluye el escalado y el recorte.
   Consultar <<structure-image-styles>> para más información.
(((Instalación,definición)))
[[glossary-installing]] Installing::
   Preparar el Drupal core o cualquier tema o módulo contribuido para su uso. En
   el caso del Drupal core, esto significa descargar los archivos necesarios,
   crear la base de datos y configurar y ejecutar el script de instalación.
   Consultar <<install-decide>> para más información.
(((LAMP (Linux Apache MySQL PHP),definición)))
(((Linux Apache MySQL PHP (LAMP),definición)))
[[glossary-lamp]] LAMP::
   Acrónimo de _Linux, Apache, MySQL y PHP_: el software del servidor web sobre
   el que se ejecutan habitualmente los scripts (aunque se pueden usar otros
   sistemas operativos, servidores web y bases de datos). Consultar
   <<install-requirements>> para más información.
(((Log,definición)))
[[glossary-log]] Log::
   Lista de eventos registrados en el sitio, como datos de uso, datos de
   rendimiento, errores, avisos e información operativa. Consultar
   <<prevent-log>> para más información.
(((Menú,definición)))
[[glossary-menu]] Menú::
   Conjunto de enlaces usado para la navegación en un sitio, que puede
   organizarse jerárquicamente. Consultar <<menu-concept>> para más
   información.
(((Módulo,definición)))
[[glossary-module]] Módulo::
   Software (normalmente PHP, JavaScript y/o CSS) que amplía las
   características del sitio y añade funcionalidad. El proyecto Drupal distingue
   entre módulos _<<glossary-drupal-core,core>>_ y
   _<<glossary-contributed,contributed>>_. Consultar <<understanding-modules>>
   para más información.
(((Ruta,definición)))
[[glossary-path]] Ruta::
   La última parte, única, de la <<glossary-url,URL>> interna que el sistema
   asigna a una página del sitio, que puede ser una página orientada al
   visitante o una página de administración. Por ejemplo, la URL interna de la
   página Acerca de de su sitio podría ser _http://example.com/node/5_, y en ese
   caso la ruta es _node/5_. Véase también <<glossary-alias,Alias>>. Consultar
   <<content-paths>> para más información.
(((Permiso,definición)))
[[glossary-permission]] Permiso::
   La capacidad de realizar alguna acción en el sitio, como editar un tipo
   concreto de <<glossary-content,content>> o ver los perfiles de usuario.
   Véase también <<glossary-role,Role>>. Consultar <<user-concept>> para más
   información.
(((Campo de referencia,definición)))
[[glossary-reference-field]] Reference field::
   <<glossary-field,Field>> que representa una relación entre una
   <<glossary-entity,entity>> y una o varias entidades más, que pueden ser del
   mismo <<glossary-entity-type,entity type>> o de otro tipo. Por ejemplo, en un
   sitio de mercado de agricultores, un content item de receta podría tener un
   campo de referencia al proveedor (también un content item) que publicó la
   receta. Los campos de <<glossary-taxonomy-term,Taxonomy term>> también son
   campos de referencia. Consultar <<structure-reference-fields>> para más
   información.
(((Región,definición)))
[[glossary-region]] Región::
   Área definida de una página donde se puede colocar <<glossary-content,content>>,
   como la cabecera, el pie de página, el área principal de contenido, la barra
   lateral izquierda, etc. Las regiones las definen los <<glossary-theme,themes>>,
   y el contenido que se muestra en cada región está contenido en
   <<glossary-block,blocks>>. Consultar <<block-regions>> para más información.
(((Relación,definición)))
[[glossary-relationship]] Relationship (in a View)::
  Ampliación de los datos que se muestran en una vista, relacionando el
  contenido base con otras entidades de contenido. Consultar <<views-parts>>
  para más información.
(((Repositorio,definición)))
[[glossary-repository]] Repositorio::
   Ubicación donde un sistema de control de versiones almacena todos los
   archivos y directorios de un proyecto. Consultar <<install-tools>> para más
   información.
(((Responsive,definición)))
[[glossary-responsive]] Responsive::
   Se dice que un sitio o un <<glossary-theme,theme>> es responsive si ajusta su
   presentación en respuesta al tamaño de la pantalla del navegador, la
   impresora u otro tipo de salida. Véase también
   <<glossary-breakpoint,Breakpoint>>. Consultar <<structure-image-responsive>>
   para más información.
(((Revisión,definición)))
[[glossary-revision]] Revisión::
   Registro del estado pasado o presente de una <<glossary-entity,entity>> de
   <<glossary-content,content>>, a medida que se edita con el tiempo. Consultar
   <<planning-workflow>> para más información.
(((Rol,definición)))
[[glossary-role]] Rol::
   Conjunto de <<glossary-permission,permissions>> con nombre que se puede
   aplicar a una <<glossary-user,user account>>. Consultar <<user-concept>> para
   más información.
(((Actualización de seguridad,definición)))
[[glossary-security-update]] Security update::
   <<glossary-update,Update>> que corrige un error relacionado con la seguridad,
   como una vulnerabilidad. Consultar <<security-concept>> para más
   información.
(((Sesión,definición)))
[[glossary-session]] Sesión::
  Información sobre las interacciones de cada visitante con el sitio, como si ha
  iniciado sesión y sus cookies. Consultar <<understanding-data>> para más
  información.
(((Sitio de ensayo,definición)))
[[glossary-staging-site]] Staging site::
   Copia del sitio en producción que se puede usar para hacer pruebas o para
   presentar los cambios al cliente para su aprobación. Consultar
   <<install-dev-sites>> para más información.
(((Estado,definición)))
[[glossary-state]] Estado::
   Información de naturaleza temporal sobre el estado actual de su sitio, como el
   momento en que se ejecutó por última vez <<glossary-cron,cron>>, etc. Véase
   también <<glossary-content,Content>> y
   <<glossary-configuration,Configuration>>. Consultar <<understanding-data>>
   para más información.
(((Taxonomía,definición)))
[[glossary-taxonomy]] Taxonomía::
   El proceso de clasificar <<glossary-content,content>>. Consultar
   <<structure-taxonomy>> para más información.
(((Término de taxonomía,definición)))
[[glossary-taxonomy-term]] Taxonomy term::
   Término usado para clasificar <<glossary-content,content>>, como una etiqueta
   o una categoría. Véase también <<glossary-vocabulary,Vocabulary>>. Consultar
   <<structure-taxonomy>> para más información.
(((Formato de texto,definición)))
[[glossary-text-format]] Text format::
   <<glossary-configuration,Configuration>> que define el procesamiento que se
   aplica al texto introducido por el usuario antes de mostrarlo en el
   navegador. Puede incluir eliminar o limitar etiquetas HTML, o convertir
   <<glossary-url,URLs>> en enlaces. Consultar <<structure-text-formats>> para
   más información.
(((Tema,definición)))
[[glossary-theme]] Tema::
   Software y archivos de recursos (imágenes, CSS, código PHP y/o plantillas)
   que determinan el estilo y la disposición del sitio. El proyecto Drupal
   distingue entre temas _<<glossary-drupal-core,core>>_ y
   _<<glossary-contributed,contributed>>_. Consultar <<understanding-themes>>
   para más información.
(((UI (User Interface),definición)))
[[glossary-ui]] UI::
   Acrónimo de <<glossary-user-interface,_User Interface_>>.
(((Actualización,definición)))
[[glossary-update]] Update::
   Una versión más reciente del software de su sitio, ya sea del
   <<glossary-drupal-core,Drupal core>> o de un <<glossary-module,module>> o
   <<glossary-theme,theme>>. Véase también
   <<glossary-security-update,Security update>>. Consultar <<security-concept>>
   para más información.
(((URL (Uniform Resource Locator),definición)))
(((Uniform Resource Locator (URL),definición)))
[[glossary-url]] URL::
   La dirección única de una página web en la web. Por ejemplo,
   https://example.com/node/7. Consultar <<content-paths>> para más
   información.
(((Usuario,definición)))
[[glossary-user]] Usuario::
   Persona que interactúa con el sitio, ya sea con la sesión iniciada o de forma
   <<glossary-anonymous,anonymous>>. Consultar <<user-concept>> para más
   información.
(((User Interface (UI),definición)))
[[glossary-user-interface]] User interface::
   El texto, los estilos y las imágenes que son visibles en un sitio, separados
   lógicamente en la interfaz de usuario para los visitantes del sitio y la
   interfaz de usuario administrativa.
(((Usuario uno,definición)))
[[glossary-user-one]] User one (User 1)::
   La cuenta de <<glossary-user,user>> inicial que se crea cuando
   <<glossary-installing,instala>> el sitio (cuyo número de ID es 1).
   Automáticamente tiene todos los <<glossary-permission,permissions>>, aunque
   no se le asigne un <<glossary-role,role>> administrativo. Consultar
   <<user-admin-account>> para más información.
(((Version Control System (VCS),definición)))
(((VCS (Version Control System),definición)))
[[glossary-vcs]] Version Control System::
   Software que guarda copias de los archivos y el historial de revisiones en un
   <<glossary-repository, repository>> y le permite añadir, eliminar y
   actualizar archivos. Consultar <<install-tools>> para más información.
(((Vista,definición)))
[[glossary-view]] Vista::
   Listado con formato de datos; normalmente, los datos provienen de
   <<glossary-entity,entities>> de <<glossary-content,content>>. Por ejemplo, en
   un sitio de mercado de agricultores, podría crear un
   <<glossary-content-item,content item>> para cada proveedor. Después podría
   crear una vista que genere una página de listado que muestre una imagen en
   miniatura y una descripción corta de cada proveedor, con un enlace al content
   item de la página completa. Con los mismos datos, también podría crear una
   vista que genere un bloque de proveedores nuevos, que mostraría información
   de los proveedores añadidos más recientemente. Consultar <<planning-modular>>
   para más información.
(((Modo de visualización,definición)))
[[glossary-view-mode]] View mode::
   Conjunto de <<glossary-configuration,configuration>> de
   <<glossary-field-formatter,field formatter>> para todos los
   <<glossary-field,fields>> de una <<glossary-entity,entity>> de
   <<glossary-content,content>>, algunos de los cuales pueden estar ocultos.
   Cada <<glossary-entity-subtype,entity subtype>> puede tener uno o varios
   modos de visualización definidos; por ejemplo, los
   <<glossary-content-type,content types>> normalmente tienen los modos de
   visualización _Full_ y _Teaser_, donde el modo _Teaser_ muestra menos campos
   o campos recortados. Consultar <<structure-view-modes>> para más
   información.
(((Vocabulario,definición)))
[[glossary-vocabulary]] Vocabulario::
   Grupo de <<glossary-taxonomy-term,taxonomy terms>> entre los que elegir al
   clasificar <<glossary-content,content>> de una forma concreta, como la lista
   de todas las categorías de proveedores de un sitio de mercado de
   agricultores. Técnicamente, los vocabularios son el
   <<glossary-entity-subtype,entity subtype>> del
   <<glossary-entity-type,entity type>> de término de taxonomía. Consultar
   <<structure-taxonomy>> para más información.

(((Asistente,definición)))
[[glossary-wizard]] Asistente::
   Formulario web que le permite rellenar unos pocos valores y crea algo con
   valores predeterminados razonables en función de los valores que haya
   elegido. Por ejemplo, hay asistentes para crear <<glossary-view,views>> de
   distintos tipos. Consultar <<views-create>> para más información.
(((WYSIWYG (What You See Is What You Get),definición)))
(((What You See Is What You Get (WYSIWYG),definición)))
[[glossary-wysiwyg]] WYSIWYG::
   Acrónimo de _What You See is What You Get_ ("lo que ves es lo que
   obtienes"), que hace referencia a un método de edición de
   <<glossary-content,content>> en el que lo que se ve en la pantalla de edición
   se asemeja mucho al resultado final. Consultar
   <<structure-text-format-config>> para más información.
